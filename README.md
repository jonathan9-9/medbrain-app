# Clinical Operations RAG Document Lookup

A small retrieval-augmented generation (RAG) application for answering clinical-operations and health-guidance questions from an indexed document corpus. The backend retrieves relevant chunks from Pinecone, uses Gemini to generate a grounded answer, and attaches backend-verified citations to the response. Safety guardrails prevent personal medical-advice questions from reaching normal answer generation and return a deterministic unanswerable response when retrieval confidence is too low.

## What it does

The application follows this pipeline:

```text
Document → parse → chunk → embed → Pinecone
                                      ↓
Question → embed → retrieve → Gemini → cited answer
```

The response stream includes retrieval status, answer tokens, citations, and completion events. Source citation metadata is resolved by the backend from retrieved chunks rather than trusting model-generated source metadata.

## Local setup

From the repository root, activate the backend virtual environment:

```bash
source backend/.venv/bin/activate
```

Create `backend/.env` with the required server-side credentials:

```env
GEMINI_API_KEY=your_gemini_api_key
PINECONE_API_KEY=your_pinecone_api_key
```

Install backend dependencies if needed:

```bash
python -m pip install -r backend/requirements.txt
```

### Run locally

Start the backend with the project's normal FastAPI/Uvicorn command and start the Next.js frontend with the project's frontend command. The live application uses the backend on `localhost:8000` and the frontend on `localhost:3000`.

If the repository provides a Make target for local development, prefer that single command; otherwise run the backend and frontend from their respective directories.

## Ingestion

The corpus must be ingested before retrieval or evaluation. From the repository root, with the backend virtual environment active:

```bash
python -m ragcore.ingestion.run
```

The ingestion flow parses source documents, chunks the extracted text, creates embeddings, and upserts vectors plus metadata into the configured Pinecone index.

> **Current limitation:** embedding generation is still one chunk per request. A production version should batch embedding requests, pass output dimensionality consistently, validate embedding dimensions before indexing, and add retries/checkpointing for large corpora.

## Evaluation

The evaluation suite contains exactly 15 cases:

- 8 standard factual questions
- 2 multi-document synthesis questions
- 3 unanswerable questions
- 2 personal-medical-advice refusal questions

Run it from the repository root:

```bash
python -m eval.run_eval
```

or, if the Makefile target is configured:

```bash
make eval
```

The harness runs the same `ChatService` used by the application, computes status and retrieval metrics, applies answer-quality judging to a small representative subset, prints a summary, and writes:

```text
 eval/report.json
```

The report separates application/status failures from external evaluation errors such as Gemini quota exhaustion.

## Testing and CI

CI is intended to run linting, type checking, and the repository's meaningful unit/integration tests on push. The evaluation harness is separate from CI because it requires live Gemini and Pinecone credentials and consumes external API quota.
